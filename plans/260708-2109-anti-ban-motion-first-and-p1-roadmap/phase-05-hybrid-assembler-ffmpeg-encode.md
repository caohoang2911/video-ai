# Phase 5: Hybrid assembler + ffmpeg encode

## Overview
Assemble a beat sequence that mixes normalized video b-roll and Ken Burns stills, and replace MoviePy's
`write_videofile` (documented ~10x regression in 2.x) with an ffmpeg-native encode using M1's
`h264_videotoolbox` hardware encoder. Target: 10-min render in ~6-9 min instead of 40+.

This phase is two clearly separate stages in the same file (see "Stage breakdown"): **5a**, the ffmpeg
encode refactor, does NOT depend on phase 4 and is buildable/verifiable today on the current
Ken Burns/stills-only path; **5b**, motion b-roll segments + hybrid concat, depends on phase 4's
normalized clips. Sequence 5a first.

## Requirements
- Functional: per beat, emit a segment = trimmed normalized video clip OR Ken Burns image (existing zoompan);
  concat body segments to `base.mp4`; ONE encode pass burns segment-level captions + mixes ducked
  narration/music onto `base.mp4` (body-first, preserving audio/caption t=0) to produce `body.mp4`;
  THEN concat pre-rendered intro + `body.mp4` + outro → `final.mp4`. Encode H.264 yuv420p via
  videotoolbox. Output `output/<id>/final.mp4`, state → rendered.
- Functional: intro/outro branding cards are generated by pure ffmpeg (no MoviePy objects on this
  path) at the SAME spec as every other segment: 1920×1080, 24fps CFR, yuv420p, `setsar=1`, silent AAC.
- Non-functional: ONE project fps = 24 everywhere (Ken Burns zoompan, b-roll normalize, branding cards,
  concat boundary) — no 30fps survivors; pure-ffmpeg render path (no MoviePy `write_videofile`);
  libx264 software fallback flag; idempotent resume (existing pattern); files <200 lines; intermediate
  working files (normalized clip copies, per-beat segments, `base.mp4`/`body.mp4`) are deleted after a
  successful final encode.

## Architecture
Move the render path off MoviePy. `caption_whisper.py` already yields `{start,end,text}` → write an SRT and
burn via ffmpeg `subtitles=` filter (removes the TextClip/Pillow-pin fragility). Ken Burns stays as ffmpeg
`zoompan` (existing `kenburns_ffmpeg.py`, now locked to 24fps — see below). New `segment_builder.py` (5b)
produces one MP4 segment per beat (video-clip trim/loop-to-duration OR Ken Burns still). `ffmpeg_encode.py`
(5a) does the concat + caption burn + audio mux + videotoolbox encode. `video_builder.py` orchestrates
and updates DB state.

**Body-first mux ordering (not a single full-timeline filtergraph):** `captions.srt` and `narration.mp3`
are body-relative — t=0 is the first BODY beat, not the start of the intro. Burning captions and muxing
audio over the full intro+body+outro timeline in one filtergraph would shift everything by the intro's
length (~3s) for the WHOLE video. Instead: (1) concat body segments only → `base.mp4`; (2) ONE ffmpeg
pass burns `captions.srt` and muxes ducked narration/music onto `base.mp4`, preserving its own t=0 →
`body.mp4`; (3) THEN concat pre-rendered `intro.mp4` + `body.mp4` + `outro.mp4` → `final.mp4` (stream-copy
concat, no re-encode of already-branded audio/captions). Intro/outro never see captions or narration.

**Branding without MoviePy:** `branding.py`'s `load_intro`/`load_outro` currently return MoviePy clip
objects, which the ffmpeg render path can't consume. Rewrite them to synthesize intro/outro cards via
pure ffmpeg (`color` background + `drawtext` for the title card, silent AAC track via `anullsrc`) at the
exact segment spec: 1920×1080, 24fps CFR, yuv420p, `setsar=1`. Any user-supplied `intro.mp4`/`outro.mp4`
is routed through the same normalize step (scale/pad/fps/sar) so it matches the concat boundary exactly.

**24fps lock (F7):** `kenburns_ffmpeg.py` currently hardcodes `FPS = 30`; phase 4's b-roll is normalized
to 24fps. Concatenating 30fps Ken Burns segments with 24fps b-roll segments without an explicit CFR
normalize inflates the timeline (empirically 4s → 5s per mismatched segment) and desyncs captions burned
in the same pass. Lock the WHOLE project to 24fps: change `kenburns_ffmpeg.py`'s `FPS` to 24, and add an
explicit CFR `fps=24` at every concat boundary — prefer the `concat` FILTER (`-filter_complex
"[0:v]fps=24,...[0v];...concat=n=N:v=1:a=0"`) with per-input `fps=24`, over the concat DEMUXER (which
only stream-copies and cannot normalize mismatched fps).

**Retention (F12):** normalized b-roll copies, per-beat segment MP4s, and `base.mp4`/`body.mp4`
intermediates are working files, not final artifacts — delete them immediately after `final.mp4` encodes
successfully. The full `output/<id>/` working tree is pruned once the video reaches `published` (phase
07 adds a disk-usage line to `ops/health`; phase 05 only deletes the render-time intermediates).

## Implementation Steps

### 5a (no dependencies — start first)
1. `srt_writer.py`: `write_srt(segments, path)` from whisper output.
2. `kenburns_ffmpeg.py`: change `FPS = 30` to `FPS = 24` (single-line project-wide fps lock).
3. `branding.py`: replace `load_intro`/`load_outro` (MoviePy) with ffmpeg synth: `color=c=...:s=1920x1080:
   d=<dur>,drawtext=...` video + `anullsrc=r=44100:cl=stereo` silent audio, muxed and encoded to
   `intro.mp4`/`outro.mp4` at 24fps CFR, yuv420p, `setsar=1`. Route any user-supplied intro/outro.mp4
   through the same scale/pad/fps/sar normalize so it matches exactly.
4. `ffmpeg_encode.py`: (a) concat body segments (existing Ken Burns-only sequence for 5a; b-roll mix
   arrives in 5b) with the concat FILTER + per-input `fps=24` → `base.mp4`; (b) ONE pass:
   `-vf subtitles=captions.srt` + audio = narration + `music*0.2` ducked (amix or sidechain) onto
   `base.mp4`, preserving t=0 → `body.mp4`; (c) concat `intro.mp4` + `body.mp4` + `outro.mp4` (stream-copy,
   no re-encode) → `final.mp4`, encode `-c:v h264_videotoolbox -b:v 8M -pix_fmt yuv420p -c:a aac`.
   Env/flag `ENCODER=libx264` fallback. Delete `base.mp4`/`body.mp4`/per-beat segments once `final.mp4`
   is confirmed valid (ffprobe).
5. `video_builder.py`: replace the MoviePy composite/`write_videofile` block with: segment step (Ken
   Burns-only until 5b) → srt_writer → ffmpeg_encode (body-first) → delete intermediates. Keep the
   existing idempotent resume + `state=rendered` + `duration_sec` (from ffprobe). Keep `close()`-free
   (no MoviePy clips on the render path).
6. `caption_whisper.py`: keep `transcribe()`; SRT replaces TextClip list (leave TextClip builder unused/removed).
7. Verify: compile + import; ffprobe of a test render → h264, yuv420p, 1920×1080, exactly 24fps CFR,
   has audio + burned captions; body audio/captions land at the correct offset (intro length does not
   shift them); videotoolbox path used on M1, libx264 fallback works; render time materially <
   MoviePy baseline; intermediate files are gone after a successful run.

### 5b (depends on phase 4)
8. `segment_builder.py`: `build(beat, asset, duration, out)` → if `video_broll`: ffmpeg trim/`tpad`/loop to
   exact beat duration at 1920×1080@24fps; if still: existing Ken Burns zoompan (now 24fps). Return segment path.
9. `ffmpeg_encode.py`/`video_builder.py`: swap the 5a Ken-Burns-only body segment list for
   `segment_builder`'s mixed video/still sequence; everything downstream (body-first mux, concat,
   encode, cleanup) is unchanged from 5a.
10. Verify: compile + import; a beat with obvious footage keywords resolves to a normalized 1080p24
    clip trimmed to its beat duration; still-beat fallback still renders via Ken Burns; ordering matches
    `shot_list`; concat boundary still exactly 24fps CFR (no seam hitch/duration inflation).

## Risk Assessment
- videotoolbox quality vs libx264: verify at first real render; keep libx264 flag; tune bitrate/`-q:v`.
- ffmpeg filtergraph complexity (subtitles + amix + concat): build incrementally, body-first per the
  Architecture section above (never one full-timeline filtergraph); log full ffmpeg stderr on failure.
- Variable b-roll duration vs beat length: `tpad`/loop/trim to exact duration; never leave gaps.
- fps drift if a future asset path bypasses the 24fps normalize: the concat-filter `fps=24` per input is
  a hard backstop even if an upstream normalize step is skipped.
- Dropping MoviePy render removes Pillow-pin/TextClip fragility (a net risk reduction).
- Deleting intermediates too eagerly could remove data needed for a failed-encode retry: only delete
  AFTER `final.mp4` is confirmed valid via ffprobe, never before.
